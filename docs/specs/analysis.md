# 分析機能 仕様書

公開サイトの分析を、競合が標準で出している項目まで揃える。対象はロト6・ロト7・ミニロト。機能ページには数字と操作だけを出す。解説・免責は既存の免責ページに置く。検索の title・h1・URL は `docs/specs/seo-strategy.md` に従う（LOTO6通信のオーガニック順位帯と見出し構造が根拠）。

実施日は未定。検証対象は本番URL（ドメイン確定後）。改修の判定は表示確認。

## 目的

来訪者が「数字の出方」を、回数・間隔・組み合わせ・形の四方向から同じ期間で見られるようにする。

競合（LOTO6通信、loto6.jp、thekyo、楽天の出現回数）が標準で持つ分析を、種目横断のこのサイトでも欠かさない。予想投稿・購入導線は目的に含めない。

## 範囲と対象外

入れる（分析）:

1. 期間切替
2. 出現回数（本数字／ボーナス／合計、期待回数、グラフ）
3. 連休（出ていない期間）と連続出現
4. 同時出現（2個・3個）
5. 構成（奇数偶数、合計、連番、下一桁、幅、帯）
6. 出目表
7. 前回との重なりと、出た直後の次回復帰
8. 数字ページ（1数字の回数・相性・出た回）

入れない:

- みんなの予想、掲示板、クイックピックの投票集計
- 購入シミュレーション、購入ボタン
- セット球・抽せん会場（DBに項目がない）
- マークシートの全パターン列挙
- 金額ランキング（既存の `/ranks` のまま。本仕様の対象外）
- 出目生成（既存の `/generate` のまま。分析結果の入力にはしない）

## 共通仕様

### 期間

分析5画面と API で同じ期間キーを使う。既定は `all`（第1回〜最新）。

| キー | 意味 |
| --- | --- |
| `all` | 全期間 |
| `draws50` | 直近50回 |
| `draws100` | 直近100回 |
| `draws500` | 直近500回（開催が足りなければ全件） |
| `years5` | 直近5年 |
| `years10` | 直近10年 |

画面上部に期間の切替を置く。切替は同一画面内。クエリ `?period=` を付け、再読込しても同じ期間を開く。期間が足りないキーは出さない（例: 開催70回のとき `draws100` `draws500` は出さない。`draws50` と年・全期間は出す）。

各画面の表の直上に、対象の回号と日付と開催回数を1行で出す。例: `第0001回（2000年10月5日）〜第2143回（2026年10月5日）　2143回`。

出目表だけ期間キーではなく「表示回数目」を使う（後述）。集計の母数は出目表では直近の表示件数。

### 母数

本数字の出現回数の分母は開催回数。1回の本数字は種目の本数字個数。期待回数は `開催回数 × 本数字個数 ÷ 数字の個数`（数字の個数は max−min+1）。

ボーナスの分母も開催回数。1回のボーナス個数は種目の `bonus_count`（ロト7は2）。期待回数は `開催回数 × bonus_count ÷ 数字の個数`。

「本+ボーナス」の回数は、その回の本数字集合とボーナス集合の和集合では数えない。本の出現回数とボーナスの出現回数を足す（同じ回で本とボーナスに同時に出ることはない前提）。

割合の表示は小数第1位、期待との差は整数（四捨五入しない、切り捨てなしで四捨五入）。

### 種目差

| | ロト6 | ロト7 | ミニロト |
| --- | --- | --- | --- |
| 本 | 6 | 7 | 5 |
| ボーナス | 1 | 2（`bonus` と `bonus2`） | 1 |
| 数字 | 1–43 | 1–37 | 1–31 |

位置（第1数字〜）は、公表どおり小さい順に並んだ本数字を第1から数える。抽せん機械の出た順は持たない。

帯（3分割）は番号を低・中・高に等分する。余りは高側へ。

| 種目 | 低 | 中 | 高 |
| --- | --- | --- | --- |
| ロト6 | 1–14 | 15–29 | 30–43 |
| ロト7 | 1–12 | 13–25 | 26–37 |
| ミニロト | 1–10 | 11–21 | 22–31 |

6分割は番号を6帯にほぼ等分する（ロト6は 1–7, 8–14, 15–21, 22–28, 29–35, 36–43）。ロト7・ミニロトも max を6で割る。

### 操作

PC・スマホとも期間切替は横スクロールしないボタン列。表は既存の `.table-wrap` で横スクロール可。ソートは回数の降順が既定。出現回数表は回数／経過／数字の見出しクリックで並べ替え。グラフは表と同期し、別ライブラリは使わず CSS の幅で棒を出す。

空は「分析できる当せんデータがありません」。エラーは既存の `.error`。

## 機能

### 1. 出現回数

経路: `/{game}/freq`

出す列:

- 順位
- 数字
- 本数字の回数
- 本数字の割合（開催に対する、その数字が本に出た回の割合 = 回数÷開催。既存の `probability` と同じ）
- 期待回数
- 期待との差（回数−期待）
- ボーナス回数（ロト7は2個とも加算）
- 本+ボーナス
- 最終（日付）
- 経過（本数字が出てからの開催数。今回0、未出は開催回数）
- 最長連休（本数字が連続して出なかった開催数の最大。未出は開催回数）
- 連続（本数字が連続して出た最長。未出は0。今回連続中ならその長さ）
- 棒（本数字回数、最大値を100%）

切替:

- 集計対象: 本数字 / ボーナス / 本+ボーナス。既定は本数字。棒と順位・期待はこの対象に合わせる。本数字のとき期待は本の期待、ボーナスのときボーナスの期待。
- 並び: 多い順 / 少ない順 / 経過が長い順 / 数字順。

グラフは表の上に横棒リスト（数字と回数）。表と二重でもよい。印刷・画像保存は不要。数字列は `/{game}/n/{nn}` へリンクする。

### 2. 連休と連続（出現回数に内包）

経過・最長連休・連続は出現回数表の列とする。独立ページは作らない。

定義:

- 経過: 対象期間の最新回から見て、本数字が最後に出た位置までの開催数。対象期間内に一度も出ていなければ開催回数。ボーナス切替時はボーナスの最終で計算する。
- 最長連休: 対象期間内で、その数字が本（または切替対象）に出なかった連続開催の最大。期間の先頭・末尾の切れも連休に含める。
- 連続: 対象期間内で出た連続開催の最大。

### 3. 同時出現

経路: `/{game}/pairs`

本数字のみ。ボーナスは含めない。

- 2個: 上位30件と下位10件（1回以上出た組に限る。出た組が40未満なら全件を回数降順で出し、下位枠は省略）
- 3個: 上位20件と下位10件（同様）

列: 数字、回数、割合（÷開催）、期待回数。2個の期待は `開催 × C(本数字個数,2) / C(数字個数,2)`。3個は `C(本,3) / C(数字個数,3)`。

表の数字は `/{game}/n/{nn}` へリンクする。

### 4. 構成

経路: `/{game}/shape`

すべて本数字。対象期間の開催が母数。各ブロックは見出し＋表。解説文は置かない。

**奇数偶数**  
偶数n個・奇数（本数字個数−n）個の回数と割合。全パターンを偶数0から本数字個数まで出す（0回の行も出す）。

**合計**  
- 要約: 平均、中央値、最小、最大、最頻  
- 分布: 10刻みの回数（既存 `_sum_bins`）。棒を付ける。

**連番**  
ソートした本数字で、差が1の隣接ペア数（0 〜 本数字個数−1）の回数と割合。  
最長ラン（連続して1ずつ増える長さ、単独は1）の回数も出す。

**下一桁**  
0–9。本数字の下一桁の延べ回数（1回で本数字個数だけ加算）。期待は `開催 × 本数字個数 ×（その桁を持つ数字の個数）÷ 数字個数`。数字の個数が桁で違う（43なら 3 が5個、0 が4個など）ので期待は桁ごとに変える。

**幅**  
`最大本数字 − 最小本数字` の分布（値ごとの回数）。要約に平均・最小・最大。

**帯**  
1回あたり低・中・高の本数字個数の平均と、3帯の延べ回数。6分割の延べ回数表も出す。

**曜日**  
抽せん日の曜日（月〜日）の開催回数。出ない曜日は0で出す。

### 5. 出目表

経路: `/{game}/grid`

行は新しい回が上。列は 01 から種目の最大数字。マスは本数字・ボーナス（ロト7は両方）・なし。本とボーナスで色を分ける。回号と日付を行頭に出す。

表示件数: 20 / 50 / 100。既定 50。クエリ `?rows=`。

ハイライト（同時に複数可）:

- 奇数
- 連番（その回の本数字で差1の組）
- 連続出現（直前の行と同じ本数字）

列の上に数字を置き、狭い画面では横スクロール。

### 6. 前回の当選番号を含む回数

経路: `/{game}/follow`

ボーナスは見ない。第1回は「前回」がないので全体回数の対象外（割合の分母は期間内の開催数）。

**全体**  
- 含まない／含む: 直前の回と本数字が1個でも重なるか  
- 2連続: 前回と今回に同じ数字があり、前々回にはない（前々回が無い組は含む側を2連続に数える）  
- 3連続: 前々回・前回・今回の3回に同じ数字がある  
含む／2連続／3連続は互いに排他ではない（回単位）。

**数字ごと**  
その数字が出た回について、前回に出ない／前回にも出る／率／2連続／3連続。2連続＋3連続＝前回にも出る。行の数字は `/{game}/n/{nn}` へ。

### 7. 数字ページ

経路: `/{game}/n/{nn}`

対象期間は出現回数と同じ `period`（既定 `all`）。

出すもの:

- 本数字回数、ボーナス回数、本+ボーナス、期待、最終、経過、最長連休、連続
- 一緒に出た本数字 上位20（回数）
- その数字が本に出た回（新しい順、20件＋さらに表示）

範囲外の `{nn}` は 404。出現回数表の数字列もここへリンクする。

## API

既存 `GET /api/{game}/trends` を拡張する。金額ランキング用の呼び出しは残す。

### 期間パラメータ

`period` を追加する。`years` は互換のため残し、`period` が無いときだけ使う。`period` があるときは `years` を無視する。不正値は 400。

### レスポンス（追加・変更）

既存の `frequency` `pairs` `triples` `odd_even` `sums` `meta` `latest` `prize_ranks` は残す。

`frequency[]` に次を必ず含める。

- `bonus_count`（`bonus` + `bonus2`）
- `main_plus_bonus` = `count` + `bonus_count`
- `expected_main`
- `expected_bonus`
- `max_rest`（最長連休、本数字）
- `max_streak`（最長連続、本数字）
- `last_draw_no` `last_draw_date` `draws_since_last`（本数字）

`pairs` / `triples` に `expected` を足す。件数上限は 2個は全組を返さず、上位30+下位10を `pairs_high` `pairs_low` に分けてもよい。その場合旧 `pairs` は上位30と同一。

追加キー:

```
period, period_label
shape.odd_even          // 既存 odd_even と同型で 0回行を含む
shape.sum_summary       // mean, median, min, max, mode
shape.sum_bins          // {label, draws}[]
shape.consecutive_pairs // {adjacent_count, draws, rate}[]
shape.consecutive_run   // {run_length, draws, rate}[]
shape.last_digit        // {digit, count, expected}[]
shape.span              // summary + {span, draws}[]
shape.bands             // {id, label, min, max, count}[]  3分割と6分割
shape.band_mix          // 1回あたり低中高の平均個数
shape.weekday           // {weekday: 0-6, draws}[]  0=月
follow.summary          // {key: none|any|streak2|streak3, draws, rate}[]
follow.by_number        // {number, without_prev, with_prev, with_prev_rate, streak2, streak3}[]
follow.highlights       // with_prev_high / streak2_high / rate_high / rate_low
```

出目表は集計しない。`GET /api/{game}/history?limit=&offset=0` を流用する。ハイライトはフロントで計算する。

数字ページは `GET /api/{game}/numbers/{n}`。trends の frequency 1行＋その数字を含む search と、共起上位を返す。不正な n は 404。

レート制限は検索・生成のみ。trends は現状どおり。

## 既存資産の使い方

- `src/loto6/analyze.py` を種目の min/max/main/bonus と期間スライスに対応させて拡張する。ロト7の `bonus2` をボーナス回数に含める。
- `/api/{game}/trends` が `years_ago` 固定なのを `period` に替える。
- フロントの `trends()` を期間付きにし、`freq` 以外の3画面を追加する。
- CLI `python -m loto6 analyze` は同じ集計関数を使い、公開と数値を一致させる。

## 受け入れ（表示確認）

種目3つ × 期間 `all` と `draws50` で次を目視する。

- 出現: 本／ボーナス切替、期待、棒、経過、ロト7のボーナス2個
- 同時出現: 2個・3個の回数
- 構成: 奇偶の合計が開催回数と一致、合計のビン、下一桁
- 出目表: 最新行が最新結果と一致、本とボーナスの色
- 前後: 重なりの合計が（期間開催−1）と一致
- 数字ページ: 01 と最大数字、存在しない数字は 404

ローカル確認 URL（起動中）: `http://127.0.0.1:5174/{game}/freq` ほか。本番URLはドメイン確定後に差し替える。
